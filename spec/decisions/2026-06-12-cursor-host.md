# Cursor as a Forge host

status: accepted (user-approved 2026-06-12 — choices A/B/C resolved via AskUserQuestion in the v0.4 hardening loop)
relates-to: FORGE-160, FORGE-152 (root-file split), FORGE-156 (skill farm), FORGE-88 (IHarness)

## Researched facts (cursor.com/docs, retrieved 2026-06-12)

- Project rules live in `.cursor/rules/*.mdc` (YAML frontmatter: `alwaysApply`/`description`/`globs`); plain `.md` ignored; `.cursorrules` legacy. Cursor also natively reads a root `AGENTS.md`.
- Skills: `.agents/skills/<name>/SKILL.md` and `.cursor/skills/...` are scanned natively (Cursor 2.4+), INCLUDING the compatibility paths `.claude/skills/` and `.codex/skills/`.
- Subagents: `.cursor/agents/<name>.md` (frontmatter: name/description/model/readonly/is_background); `.claude/agents/` read as a compatibility path with `.cursor/` precedence.
- `@file` imports inside `.mdc` rules are documented but CONFIRMED unreliable (forum #135663, Cursor team ack) — a rule cannot dependably auto-include `.forge/CONTEXT.md`.
- CLI: `agent -p "<prompt>"` (print mode), `--force` (no confirmations), `--output-format json|stream-json`, `--worktree`, `CURSOR_API_KEY` auth. Officially **beta** ("security safeguards still evolving").

## Decisions

1. **Breadcrumb (USER CHOICE A: inline verbatim).** `AgentKind` gains `'cursor'`; its managed artifact is `.cursor/rules/forge-context.mdc` — frontmatter `alwaysApply: true` followed by the forge marker block whose body INLINES the rendered CONTEXT.md (same `renderContext()` output upgrade already holds in memory). Because `.mdc` frontmatter must be the first bytes, cursor uses a dedicated assembly (frontmatter + marker block), not the generic prefix-prepend; `replacePrefixBlock` still manages the marker region so user content below the markers survives. The file is regenerated by `forge upgrade` exactly like CONTEXT.md and is **gitignored** (same determinism rationale: methodology is regenerated per machine; the FORGE-161 pin makes version drift reviewable).
2. **Skill farm (USER CHOICE B: `.agents/skills` canonical).** `HOST_DIRS.cursor = { skills: '.agents/skills', agents: '.cursor/agents' }` — Cursor scans `.agents/skills` natively, giving one cross-tool root; subagent definitions farm into `.cursor/agents/`. Existing `.claude/skills`/`.claude/agents` remain cross-consumed by Cursor when claude is also enabled; the cursor entries make cursor-only repos self-sufficient. Gitignore block gains `/.agents/skills/`, `/.cursor/agents/`, and `/.cursor/rules/forge-context.mdc`.
3. **Dispatch (USER CHOICE C: beta opt-in gate).** `primary_host_cli` accepts `'cursor'` ONLY when `agents.cursor_host_beta_opt_in: true` (schema refine; clear error otherwise naming the flag and the beta caveat). Under opt-in, a `CursorHarness` (subprocess-backed: `agent -p --force --output-format json`, `CURSOR_API_KEY` passthrough) implements primary dispatch; `runReview` is NOT_SUPPORTED (review hosts remain codex|gemini). `enabled_root_files` may include `cursor` with no opt-in (passive breadcrumb + farms).

## Accepted edges

- Inlined context costs ~200 lines per Cursor session (chosen over the lean pointer for reliability while `@file` imports stay broken — revisit when Cursor fixes them).
- Cursor CLI is beta; the opt-in flag is the honesty mechanism. Promotion to ungated primary host is a follow-up when the SDK reaches GA.
